The one stream: record the alert first, then send it

Outbox

The alert table is the outbox. A crash between record and send never loses an alert.

Deterministic id

Disbursement id, change sequence and rule. A replay sends the same id; the receiver drops the duplicate.

Backstop

The daily build re-tests every disbursement, so anything the stream misses is caught by morning.

Two rules: a FAILED disbursement because a customer is waiting for money, and money moving on an application whose latest decision is DECLINED, the most serious disagreement in the design. Latency is one-minute files plus a one-minute trigger, typically one to three minutes, inside a five-minute target. Health: a heartbeat each time the stream checks for work, so a quiet night is not mistaken for a fault. I rejected Flink and Spark real-time mode: seconds of latency where ops acts in minutes, and a second engine outside the catalog’s audit. The pattern scales: each new stream reads the same landing files and writes its own outbox.
